# KAPA MCP adapter

- [MCP 어댑터 유지보수 안내](MAINTENANCE.md)

- This adapter and upstream repositories may be public under the 2026-11-11 policy. Keep the MCP server local-only: stdio or authenticated loopback HTTP, never a public endpoint or tunnel. Repository visibility is not an authorization signal. Do not publish packages or add publication from the adapter; preserve existing authentication and loopback boundaries.
- This project connects existing KAPA repositories; it does not duplicate their datasets, call model APIs, update upstream content, fetch law APIs, or manage upstream review status.
- Never read credential files (`edu_gh_token.txt`, `law_oc.txt`) or expose environment secrets. Do not import upstream production code with credential fallback for read-only queries.
- Upstream repositories are read-only inputs. Build artifacts belong in isolated job directories, never upstream build folders. No arbitrary shell or filesystem read tools.
- New code: SPDX-License-Identifier: GPL-3.0-only, UTF-8, LF. No personal absolute paths in committed files.
- Work on a feature branch; no direct default-branch commits. Changes to the adapter should be independently testable with small synthetic fixtures.
- Current module contract: `config.py` provides `Settings(workspace: Path, jobs_dir: Path)` and `Settings.from_env()`; `readers.py` provides `Catalog(settings)` with `list_repositories()`, `search_questions(query='', exam=None, subject=None, round=None, limit=20, offset=0)`, `read_question(question_id)`, `search_knowledge(query, repo=None, limit=20, offset=0)`, `read_document(document_id, offset=0, max_chars=12000)`, `get_relations(material_id, review=None)`, `route_task(task)` returning JSON-serializable dicts. Document IDs use `<repo>:<allowed-relative-path>` and question IDs `edu/<1|2>/<subject>/<round>/<seq>`. `render.py` provides `RenderManager(settings)` with `start_render(exam, subject, round, question_id=None, noanswers=True)`, `get_job(job_id)`, `get_artifact(job_id, artifact_id)`.
- Configuration must be explicit via KAPA_WORKSPACE (parent of four repositories) and KAPA_JOBS_DIR, with useful startup errors; do not assume the desktop path. Repository aliases: kapa_edu_1, kapa_edu_2, kapa_skills, kapa_knowledge.

## 0.2.0 additive contracts

- Preserve all ten legacy tool names and annotations. Seven additive tools: `kapa_read_material`, `kapa_create_evidence_bundle`, `kapa_get_evidence_bundle`, `kapa_validate_evidence_bundle`, `kapa_create_render_plan`, `kapa_get_render_plan`, `kapa_start_render_plan` (17 total). `read_material(material_id)` is a Catalog metadata read for supplemental IDs, distinct from `read_document(repo:path)`. FAQ/identity-hold/pinned-law metadata never proves formal identity, historical article text or legal verification.
- `workflow.py`: `WorkflowManager(settings, catalog)`, `create_bundle(task, document_ids=None, question_ids=None, as_of=None)`, `get_bundle(bundle_id)`, `validate_bundle(bundle_id)`. Bundle top level has ordered question_ids/document_ids, digest and snapshot; no source bodies. `get_bundle` rejects stale inputs, validation returns valid/stale/checks. Reproducibility does not imply legal completeness or legal verification. Construct lazily to preserve injected catalogs without capture_evidence.
- `RenderManager(settings, *, evidence_validator=None)`: `create_plan(question_ids, noanswers=True, include_instructions=True, evidence_bundle_id=None, require_evidence=False)`, `get_plan(plan_id)`, `start_render_plan(plan_id)`. Callback `(bundle_id, question_ids)` must reject invalid/stale evidence or missing selection. Persist and enforce require_evidence at creation and start after restart. Server supplies callback and checks again at tool boundaries. Formatting-only plans may omit evidence; research output must explicitly require it and preserve coverage warnings. Existing start_render remains a formatting route.
- Default `KAPA_TRANSPORT=stdio`; only other accepted value is `streamable-http`. `HTTPSettings.from_env()` reads explicit `KAPA_HTTP_TOKEN` (32+ printable ASCII characters, no whitespace), optional `KAPA_HTTP_PORT` (1024–65535; default 8765). Bind only 127.0.0.1, require exact Host/optional Origin matching that port and one constant-time checked bearer; reject query strings. No token repr/logs, access logs, forwarded-header trust, public bind, tunnel setup or deployment. Never read credential files. Real SDK HTTP initialization and unauthorized requests must be tested.
- A local SDK protocol test is not ChatGPT/Claude chat acceptance. Require an actual product handshake before claiming it; external reachable authenticated endpoint/tunnel and account configuration remain separate setup. Do not replace actual client configuration during implementation.
- Renderer retention is an automatic metadata lookup window: at most 128 job IDs and 128 plan IDs, not a lifetime render quota. Under the existing registry OS lock, retire oldest unlocked terminal/interrupted jobs and oldest plans not pinned by live owner-locked jobs when space is needed. Register preparing jobs before copying so active plans stay pinned across processes. If nothing is eligible, reject capacity demand. Retired IDs are unavailable for lookup/start; preserve all job/PDF/plan files, with no disk-quota or automatic deletion claim and no new tool/API. Retained completed jobs embed their frozen plan. Reject stale known IDs missing from the current registry; never resurrect entries by merging cached snapshots. Terminal restore caching must retain registered-digest/registry-identity checks; requested artifacts still require SHA-256 validation.
- Native acceptance scope: isolated Claude Code 2.1.319 `mcp list` reported Connected to authenticated loopback HTTP; Codex 0.167.0 isolated `mcp add/list` passed configuration parsing only, not a native network test. No prompt/model call or actual user registration change; owned server and temporary configuration were cleaned up. Keep this distinct from SDK protocol tests and untested cloud chat acceptance.
- Evidence retention has different lookup semantics from render metadata retirement: retain at most 128 bundle directories in the active `jobs/evidence` window; at creation capacity, atomically move the oldest bundle directory to `evidence/archive/<same-bundle-id>`. Preserve all immutable files. `get_bundle`/`validate_bundle` try the exact active path then a single exact archive path, never enumerate the archive, and apply the same stored-digest and current-source checks in either location. Archived bundle IDs remain usable by plans. Bundles have no live execution state; all older bundles are eligible for archival. Serialize creation/archive/exact-ID metadata reads with the root OS lock; release it before current-source recapture. Fail bounded on busy/unsafe locks or archive collisions, never overwrite. No new tool/API and no archive disk-quota claim.
